## 二、重点案例详解

### 1. Volkswagen：工业 AI 要有统一的交付流水线和生产监控

- **来源链接**：[AWS：Volkswagen DPP 端到端 MLOps](https://aws.amazon.com/blogs/industries/how-volkswagen-and-aws-built-end-end-mlops-for-digital-production-platform/)
- **所属行业**：汽车制造，多工厂平台。
- **应用场景**：不同工厂反复建设相似的质量、维护和预测模型，数据访问、权限、训练、审批、部署与监控方式不一致。
- **核心做法**：在 Digital Production Platform 上标准化数据访问、特征准备、模型训练、注册、部署和监控；生产期定时采样输入与预测，监控数据质量、模型质量、偏差和解释性，退化时触发补采数据、重训或上游审计。
- **使用技术**：Amazon SageMaker、Model Monitor、Step Functions、EventBridge、DataZone、API Gateway、S3，以及分账户安全护栏。
- **可借鉴点**：模型包不能只有权重文件，还要绑定代码、数据版本、阈值、相机/光源配置、适用品种和审批记录。
- **光伏工厂落地想法**：为 EL、AOI、串焊外观模型建立同一份“发布清单”，先在一条线影子运行，再按设备/班次扩圈；每日对账人工复判和后续功率/返工结果。
- **开发难度评估**：高；单产线只读试点为中等。
- **预期收益**：案例称工业应用建设部署可快 2—3 倍。光伏厂首期应量化发布工时、回滚时间、跨线重复开发量和误判成本，不照搬平台级收益。

### 2. Siemens Erlangen：云端重训练，模型在产线边缘运行

- **来源链接**：[AWS/Siemens 客户案例](https://aws.amazon.com/partners/success/siemens-electronics-factory-erlangen-siemens/)
- **所属行业**：电子控制器与 PCB 装配。
- **应用场景**：人工配置或重训模型约需 30 分钟，跨边缘设备交付慢，误报影响自动检查价值。
- **核心做法**：云端完成训练与重训练，通过 Siemens Industrial Edge 管理现场部署和运行，形成从数据到模型再回产线的完整生命周期。
- **使用技术**：AWS 云训练、Siemens Industrial AI、Industrial Edge、模型生命周期管理。
- **可借鉴点**：训练位置和推理位置可以分离；发布过程要可重复，并对误报率而非仅总体准确率负责。
- **光伏工厂落地想法**：EL 新模型在服务器训练，转为标准推理包后只在一台检测机双跑；满足漏检、误拒、时延、资源占用四道门槛后再扩大到同型号设备。
- **开发难度评估**：中高。
- **预期收益**：案例称训练到部署时间缩短 80%、误报率降低 50% 以上、生命周期管理成本节省 90% 以上；均为案例方口径，需本厂复测。

### 3. IC 载板：把操作员复检变成模型迭代数据

- **来源链接**：[ASRock Industrial 案例，2025-06-27](https://www.asrockind.com/en-gb/article/236)
- **所属行业**：半导体封装/IC 载板。
- **应用场景**：细微缺陷需要边缘实时检测，不同设备和产品版本又要求模型持续优化、保持工厂级一致性。
- **核心做法**：PEGAAi 平台与边缘 AIoT 设备结合；Auto MLOps 管理模型优化，以操作员复检结果形成持续反馈，并用仪表盘跟踪 AI 表现。
- **使用技术**：边缘 AI、Auto MLOps、工业视觉、复检反馈、性能仪表盘。
- **可借鉴点**：人工复判不是模型失败后的临时补丁，而是必须结构化保存的真值来源；至少记录原判、新判、原因、缺陷区域和处理结果。
- **光伏工厂落地想法**：EL/AOI 复判界面增加“模型版本 + 原始图 + 缺陷框 + 人工修改原因”，每天生成高价值误判样本包，但不自动触发上线。
- **开发难度评估**：中等。
- **预期收益**：来源强调一致性与可扩展性，但未披露可信的量化收益，标记为**厂商案例且数字不足**。

### 4. EdgeMLOps：低算力设备也要管模型版本和远程状态

- **来源链接**：[EdgeMLOps 论文](https://arxiv.org/abs/2501.17062)
- **所属行业**：工业视觉研究验证。
- **应用场景**：资源受限边缘设备上的模型优化、部署、运行状态更新和生命周期管理。
- **核心做法**：使用 Cumulocity IoT 与 thin-edge.io 发布视觉质检模型，在 Raspberry Pi 4 上比较 FP32、静态 INT8 与动态 INT8 推理，并把检测状态写回资产管理系统。
- **使用技术**：thin-edge.io、Cumulocity IoT、模型量化、边缘推理、资产状态同步。
- **可借鉴点**：发布前必须在目标硬件实测时延、内存、温度和丢帧；“实验室准确率相同”不代表现场运行等价。
- **光伏工厂落地想法**：对接线盒、铭牌、边框外观等轻量模型，在工控机/边缘盒上建立硬件基准；低配设备优先用量化模型，但保留原模型复核通道。
- **开发难度评估**：中等。
- **预期收益**：论文报告 INT8 相对 FP32 的推理时间优势，但摘要未给出可直接复用的工厂 ROI；属于**研究验证，不是量产案例**。

### 5. 摩擦搅拌焊：模型漂移后，置信度可能比答案本身更危险

- **来源链接**：[Journal of Intelligent Manufacturing 论文](https://doi.org/10.1007/s10845-025-02569-6)
- **所属行业**：焊接质量监控。
- **应用场景**：过程、材料或设备状态变化造成数据漂移，模型输出的概率不再对应真实错误风险。
- **核心做法**：构造并评估漂移条件下的校准方法，用校准后的置信度辅助模型失效预警；论文示例的第二类漂移中，纯模型准确率已降至 82.2%。
- **使用技术**：深度学习质量监控、数据漂移、概率校准、可靠性评价。
- **可借鉴点**：上线门槛应同时看漏检率、误拒率和置信度校准误差；若“90% 置信度”的样本实际只有 75% 正确，就应降级到人工复核。
- **光伏工厂落地想法**：按版型、玻璃/胶膜批次、相机和班次切片监控 EL 模型置信度；切片样本不足时只报警，不自动重训。
- **开发难度评估**：中高。
- **预期收益**：提前识别模型失效，避免换料/换型后静默漏检；具体收益取决于人工复判真值覆盖。

### 6. 半导体材料：固定重训练节奏可能胜过每次都重新调参

- **来源链接**：[Robust and Reliable AI for Predictive Quality，2026-05](https://arxiv.org/abs/2605.07752)
- **所属行业**：半导体材料制造。
- **应用场景**：原料波动、设备退化和工艺改变使质量预测模型逐渐失准，同时现场需要可解释的风险区间。
- **核心做法**：用五年真实制造数据比较不同重训练频率与超参数优化策略；研究发现每五个生产批次固定重训练且不重复调参，在多类漂移下表现更优、计算开销更低；同时使用保形预测输出置信区间。
- **使用技术**：批次重训练、漂移评价、残差控制限、保形预测、不确定性量化。
- **可借鉴点**：不要把“检测到漂移就全量调参”当默认动作；先用历史回放比较按时间、按批次、按事件触发三种策略。
- **光伏工厂落地想法**：对层压后 EL 风险、功率虚拟量测或串焊拉力预测，输出点预测 + 区间；区间跨越质量限时转人工/实测，而不是自动判定。
- **开发难度评估**：高；已有成熟批次数据时可降至中高。
- **预期收益**：减少无效重训算力和不稳定模型发布，降低漏检风险；研究结论需按本厂漂移速度重新验证。

### 7. 工业装配线：快模型实时跑，大模型做验证

- **来源链接**：[Procedia CIRP 2025 案例](https://www.sciencedirect.com/science/article/pii/S2212827125005724)
- **所属行业**：离散装配。
- **应用场景**：活动产线需要低时延缺陷检测，同时还要有更强模型交叉验证，并与机器人流程衔接。
- **核心做法**：用产线标注图像训练优化版 YOLOv8.2s 与验证版 YOLOv8.2m；前者承担边缘实时任务，后者用于验证，检测结果与机器人流程控制集成。
- **使用技术**：YOLOv8、边缘推理、双模型验证、机器人流程控制。
- **可借鉴点**：并非所有样本都需要昂贵模型；可按低置信度、严重缺陷或新分布样本升级复核。
- **光伏工厂落地想法**：快速模型负责全量 EL 初筛，低置信度和关键缺陷进入较大模型 + 人工复核；新模型先作为第三路影子模型，不改变现有判级。
- **开发难度评估**：中高。
- **预期收益**：在节拍与检测可靠性间取得平衡；来源页面未披露可直接引用的量产收益，需本厂 A/B 回放。

## 四、结合光伏工厂的应用点子

### 点子 1：EL/AOI 新旧模型影子双跑与灰度看板

- **痛点**：新模型离线指标更好，但上线后可能因版型、相机、光源或节拍变化造成局部退化。
- **解决思路**：同一图像并行运行生产模型和候选模型；候选结果不参与放行，只对比缺陷类别、置信度、耗时、人工复判和后续处置；通过门槛后只在一台设备/一个班次灰度。
- **所需数据**：原图、组件条码、设备/相机/光源、版型、模型版本、两路输出、人工复判、返工/复测。
- **技术方案**：版本化推理 API + 事件队列 + 结果对账表 + 规则门槛 + 一键流量切回；可参考 BentoML、KServe、Argo Rollouts、KitOps。
- **复杂度**：中等。
- **收益**：降低模型升级造成批量误放/误拒的风险，把发布验收从主观试跑变为可审计证据。

### 点子 2：按版型/材料/设备切片的模型漂移雷达

- **痛点**：总体准确率稳定会掩盖某一种玻璃、胶膜、版型或相机上的恶化。
- **解决思路**：每天按关键业务维度切片，监控输入亮度/纹理、缺陷分布、置信度和人工推翻率；低样本切片标黄，不自动触发重训。
- **所需数据**：图像特征、BOM/材料批次、设备、班次、模型结果、复判、后续检测结果。
- **技术方案**：特征统计 + PSI/KS/嵌入距离 + 置信度校准 + 最小样本门槛 + 趋势看板。
- **复杂度**：中高。
- **收益**：更早发现换料、相机维护或工艺变化后的局部失效，减少静默漏检。

### 点子 3：模型发布包“六件套”与签名校验

- **痛点**：现场常只知道模型文件名，不知道其训练数据、标签定义、阈值和适用设备，回滚依赖个人记忆。
- **解决思路**：每次发布强制绑定模型、推理代码、标签字典、阈值、硬件配置和验证报告；生成摘要哈希并签名，边缘节点只拉取审批后的完整包。
- **所需数据**：Git 提交、模型制品、数据快照 ID、配置、验证指标、审批人、目标设备清单。
- **技术方案**：OCI Registry + KitOps/制品清单 + 签名验证 + 边缘拉取代理 + 审计日志。
- **复杂度**：中等。
- **收益**：将“能否复现和回滚”从口头保证变成系统能力，缩短故障定位和恢复时间。

### 点子 4：低置信度样本的复判与主动学习队列

- **痛点**：人工复判常散落在表格或聊天记录中，新模型仍重复犯同类错误。
- **解决思路**：按低置信度、新分布、严重缺陷和新材料四类自动入队；复判员必须选择原因码并标注缺陷区域；达到样本门槛后才进入下一轮训练候选集。
- **所需数据**：图像、预测、置信度、模型版本、人工判定/框选、原因码、最终处置。
- **技术方案**：任务队列 + Web 标注/复判 + 样本去重 + 数据版本 + 审批式训练流水线。
- **复杂度**：中等。
- **收益**：用有限复判工时覆盖最有信息量的样本，提高模型迭代效率和缺陷知识沉淀质量。

### 点子 5：模型升级后的质量后悔值账本

- **痛点**：发布验收只看当日抽样，无法说明新模型对后续返工、功率复测和客户抽检的真实影响。
- **解决思路**：对每次模型发布设置 7/14/30 天观察窗，回连返工、复测、库存隔离与客诉；计算若沿用旧模型时可能少/多处理多少件的“后悔值”。
- **所需数据**：新旧模型输出、处置、复测、功率、库存/出货、客诉及时间窗。
- **技术方案**：离线双模型回放 + 反事实对账 + 成本权重配置 + 发布后复盘报告。
- **复杂度**：中高。
- **收益**：让模型 KPI 与质量成本一致，避免只追求准确率或误报率单项最优。

## 五、今日最值得尝试的一个小项目

### 项目名称

**EL 模型“影子双跑 + 一键回滚”只读 MVP**

### 推荐原因

它直接解决模型升级最危险、也最容易被忽略的问题：离线测试通过不代表某条产线、某个版型和某台相机都安全。项目无需改 PLC，也不改变当前放行判定；先让生产模型与候选模型对同一批图像双跑，用真实复判和后续质量证明候选模型是否值得灰度。

### MVP 范围

- 选择一台 EL 检测机、一个高频版型和最近 2—4 周图像。
- 生产模型保持现状；候选模型仅影子运行，不向 MES 输出判级。
- 看板按缺陷类别和班次展示：一致率、候选新增拦截、候选新增误拒、低置信度率、P95 时延、CPU/GPU/内存、失败率。
- 通过门槛后只做一个班次或 10% 流量的建议态灰度；任何指标越界立即切回旧模型。
- 全程保留模型包、配置、数据范围、审批和回滚记录。

### 所需数据

EL 原图及组件条码、版型/BOM、设备与相机/光源配置、生产/候选模型版本与输出、推理耗时、人工复判、返工/复测/功率结果、当前放行记录。

### 实施步骤

1. **第 1—2 天：定义护栏**——与质量、工艺、设备共同确定严重缺陷漏检零容忍项、误拒上限、P95 时延和资源上限；写明回滚责任人。
2. **第 3—4 天：封装版本**——为两个模型建立不可变发布包，绑定权重、代码、阈值、标签、相机/光源配置和验证报告。
3. **第 5—6 天：离线回放**——回放至少 1,000 张且覆盖正常、少数类缺陷、换型后和相机维护后样本；人工复核分歧样本。
4. **第 7—8 天：在线影子运行**——候选模型只读双跑，监控时延、丢帧、资源和分布漂移；不得改写放行字段。
5. **第 9 天：门槛评审**——按版型、缺陷、设备和班次切片，任何关键切片不达标即不灰度。
6. **第 10 天：建议态灰度演练**——仅面向指定复判员展示候选建议，演练一键切回旧版本并导出完整审计记录。

### 周期与验收

- **周期**：10 个工作日。
- **验收指标**：1,000+ 张有效双跑；模型/配置/数据版本可追溯率 100%；严重缺陷分歧人工复核率 100%；P95 推理时延不超过现有节拍预算；切回旧版本 ≤ 5 分钟；0 次自动改写放行或 PLC。
- **是否上线**：MVP 结束只给出“继续影子运行 / 可进入建议态灰度 / 退回补数重训”三选一建议，不自动发布生产版本。

### 扩展方向

第二阶段扩到同型号设备并建立分批灰度环；第三阶段增加按版型/材料/相机切片的漂移雷达；第四阶段回连 7/14/30 天返工、复测和客诉，形成质量后悔值。自动放行必须另行完成 MSA、客户规则、异常降级和质量责任评审。

---

**今日判断**：光伏工厂下一步不应只是“再训练一个更准的模型”，而应先建立可证明、可分批、可回退的发布机制。把新旧模型在同一真实数据上双跑，并把分歧交给可追溯的复判，往往比一次大规模替换更快得到可信收益。
